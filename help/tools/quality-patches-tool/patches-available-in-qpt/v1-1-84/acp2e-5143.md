# ACP2E-5143 : la requête `route` GraphQL effectue le rendu du contenu de page CMS non demandé

Le correctif ACP2E-5143 corrige le problème en raison duquel la requête `route` GraphQL effectue le rendu de l’intégralité du contenu de la page CMS, y compris les widgets du Créateur de page et les listes de produits, même lorsque seuls les champs de routage d’URL sont demandés, ce qui ralentit la résolution des URL. Ce correctif est disponible lorsque la version 1.1.84 de [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) est installée. L’ID du correctif est ACP2E-5143. Notez que ce problème doit être résolu dans Adobe Commerce 2.4.10.

## Produits et versions concernés

**Le correctif est créé pour la version Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.7-p9

**Compatible avec les versions d’Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.4 - 2.4.7-p10

>[!NOTE]
>
>Le correctif peut s’appliquer à d’autres versions avec de nouvelles versions de [!DNL Quality Patches Tool]. Pour vérifier si le correctif est compatible avec votre version d’Adobe Commerce, mettez à jour le package `magento/quality-patches` vers la dernière version et vérifiez la compatibilité sur la page [[!DNL Quality Patches Tool] : Rechercher des correctifs](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=fr). Utilisez l’ID du correctif comme mot-clé de recherche pour localiser le correctif.

## Problème

Problème dans lequel la requête `route` GraphQL effectue le rendu de l’intégralité du contenu de la page CMS, y compris les widgets Page Builder et les listes de produits, même lorsque seuls les champs de routage d’URL sont demandés, ce qui ralentit la résolution des URL.

<u>Conditions préalables</u> :

Page Builder est installé.

<u>Procédure à suivre </u> :

1. Accédez à Admin > **[!UICONTROL Content]** > **[!UICONTROL Elements]** > **[!UICONTROL Pages]** et cliquez sur **[!UICONTROL Add New Page]**.
1. Saisissez les détails de la page, définissez **[!UICONTROL Enable Page]** sur **[!UICONTROL Yes]**, puis cliquez sur **[!UICONTROL Edit with Page Builder]** dans la section **[!UICONTROL Content]**. Développez **[!UICONTROL Add Content]** dans le panneau Page Builder et faites glisser un espace réservé **[!UICONTROL Products]** sur la scène, ou insérez un widget de produit de catalogue dans le contenu de la page.
1. Dans Admin, accédez à **[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL Configuration]**. Dans le panneau de gauche sous **[!UICONTROL General]**, choisissez **[!UICONTROL Web]**, puis développez **[!UICONTROL Default Pages]**. Définissez **[!UICONTROL CMS Home Page]** sur la nouvelle page, puis cliquez sur **[!UICONTROL Save Config]**.
1. Envoyez la requête GraphQL suivante :

   ```
   query ResolveURL($url: String!) {
     route(url: $url) {
       relative_url
       redirect_code
       type
       ... on CmsPage { identifier __typename }
       ... on ProductInterface { uid __typename }
       ... on CategoryInterface { uid __typename }
       __typename
     }
   }
   ```

1. Utilisez les variables suivantes pour la requête :

   ```
   { "url": "/" }
   ```

<u>Résultats attendus</u> :

La requête `route` renvoie les champs de discrimination de type et de métadonnées de routage demandés pour la page d’accueil de CMS sans effectuer le rendu de son contenu complet.

<u>Résultats réels</u> :

1. La requête `route` effectue le rendu de l’intégralité du contenu de la page d’accueil CMS même si seuls les champs de métadonnées de routage et de discriminateur de type sont demandés.
1. Les widgets de Page Builder chargent des collections de produits, ce qui augmente le temps de réponse et le nombre de requêtes de base de données par requête.
