# ACP2E-5122 : les erreurs de panier GraphQL gérées sont incorrectement écrites dans le journal des exceptions

Le correctif ACP2E-5122 corrige le problème en raison duquel les erreurs de requête de panier GraphQL gérées sont écrites dans le journal des exceptions en tant qu’erreurs d’application. Ce correctif est disponible lorsque la version 1.1.84 de [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) est installée. L’ID du correctif est ACP2E-5122. Notez que ce problème doit être résolu dans Adobe Commerce 2.4.10.

## Produits et versions concernés

**Le correctif est créé pour la version Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.8-p5

**Compatible avec les versions d’Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.4 - 2.4.9

>[!NOTE]
>
>Le correctif peut s’appliquer à d’autres versions avec de nouvelles versions de [!DNL Quality Patches Tool]. Pour vérifier si le correctif est compatible avec votre version d’Adobe Commerce, mettez à jour le package `magento/quality-patches` vers la dernière version et vérifiez la compatibilité sur la page [[!DNL Quality Patches Tool] : Rechercher des correctifs](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Utilisez l’ID du correctif comme mot-clé de recherche pour localiser le correctif.

## Problème

Les erreurs de requête de panier GraphQL gérées sont écrites dans le journal des exceptions en tant qu’erreurs d’application.

<u>Procédure à suivre </u> :

1. Envoyez une mutation `placeOrder` de GraphQL avec un ID de panier masqué non valide, expiré ou déjà détruit, tel que cette mutation :

   ```
       mutation {
           placeOrder(input: { cart_id: "test" }) {
               orderV2 {
                   id
                   number
               }
           }
       }
   ```

1. Vérifiez la réponse de GraphQL.
1. Recherchez `var/log/exception.log` erreur de panier.

<u>Résultats attendus</u> :

1. La requête GraphQL renvoie une payload d’erreur gérée face au client pour le panier non valide sans réponse *HTTP 500*.
1. L’*GraphQlNoTelEntityException* gérée n’est pas écrite dans `var/log/exception.log` et est acheminée vers un canal de journal de gravité inférieure à la place.

<u>Résultats réels</u> :

Chaque requête écrit l’exception gérée pour `var/log/exception.log` à `report.ERROR` gravité, ce qui entraîne une croissance illimitée du journal lors des requêtes répétées.
