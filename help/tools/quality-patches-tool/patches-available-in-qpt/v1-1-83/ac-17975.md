# AC-17975 : les problèmes de compatibilité PHP 8.5 affectent les commandes d&#39;interface de ligne de commande, l&#39;édition de catégories, la configuration de conception et la connexion client

Le correctif AC-17975 corrige le problème d’échec des commandes d’interface de ligne de commande, de modification de catégorie, de configuration de conception et de connexion client AJAX dans Adobe Commerce 2.4.9 lorsque PHP 8.5 est utilisé. Ce correctif est disponible lorsque la version 1.1.83 de [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) est installée. L’ID du correctif est AC-17975. Notez que ce problème devrait être résolu dans Adobe Commerce 2.4.9-p1 et 2.4.10.

## Produits et versions concernés

**Le correctif est créé pour la version Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.9

**Compatible avec les versions d’Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.9

>[!NOTE]
>
>Le correctif peut s’appliquer à d’autres versions avec de nouvelles versions de [!DNL Quality Patches Tool]. Pour vérifier si le correctif est compatible avec votre version d’Adobe Commerce, mettez à jour le package `magento/quality-patches` vers la dernière version et vérifiez la compatibilité sur la page [[!DNL Quality Patches Tool] : Rechercher des correctifs](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=fr). Utilisez l’ID du correctif comme mot-clé de recherche pour localiser le correctif.

## Problème

Les commandes d’interface de ligne de commande, l’édition de catégorie, la configuration de conception et la connexion client AJAX échouent lorsque Adobe Commerce 2.4.9 s’exécute sur PHP 8.5.

<u>Conditions préalables</u> :

PHP 8.5 est installé.

<u>Procédure à suivre </u> :

1. Exécutez la commande d’interface de ligne de commande suivante :

   ```
   bin/magento --version
   ```

1. Sur le storefront, effectuez un passage en caisse et connectez-vous pendant le passage en caisse pendant que le CAPTCHA client est activé pour la connexion et le passage en caisse.
1. Dans Admin, ouvrez une catégorie lorsqu’un attribut de catégorie a `frontend_input` défini sur `null`.
1. Dans Admin, accédez à **[!UICONTROL Content]** > **[!UICONTROL Design]** > **[!UICONTROL Configuration]**, puis cliquez sur **[!UICONTROL Edit]** dans la colonne **[!UICONTROL Action]** pour obtenir une vue de magasin.


<u>Résultats attendus</u> :

Toutes les opérations sont terminées.


<u>Résultats réels</u> :

Les opérations échouent avec des erreurs, telles que :

```
Exception #0 (Exception): Deprecated Functionality: Using null as an array offset is deprecated, use an empty string instead
/var/www/html/vendor/magento/framework/App/Config/ScopeCodeResolver.php on line 62
```

```
report.CRITICAL: Exception: Deprecated Functionality: Using null as the key parameter for array_key_exists() ... in module-captcha/Helper/Data.php on line 92
```

```
There is an error in vendor/magento/framework/Setup/Mvc/MvcApplication.php at line: 170
Undefined constant "Magento\Framework\Setup\Mvc\GLOB_BRACE"
```

```
Deprecated Functionality: Using null as an array offset is deprecated, use an empty string instead in
var/www/html/app/code/Magento/Catalog/Model/Category/DataProvider.php on line 41
```
