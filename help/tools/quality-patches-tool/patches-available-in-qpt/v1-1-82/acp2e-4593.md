# ACP2E-4593 : page CMS de restriction de site web incorrecte est diffusée sur le site web secondaire dans les storefronts multi-sites

Le correctif ACP2E-4593 corrige le problème en raison duquel la mauvaise page CMS de restriction de site web est diffusée sur le storefront du site web secondaire dans des configurations multi-sites, car la clé de cache de la page de destination n’est pas étendue par site web. Ce correctif est disponible lorsque la version 1.1.82 de [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) est installée. L’ID du correctif est ACP2E-4593. Notez que ce problème doit être résolu dans Adobe Commerce 2.4.10.

## Produits et versions concernés

**Le correctif est créé pour la version Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.5-p15

**Compatible avec les versions d’Adobe Commerce :**

* Adobe Commerce (toutes les méthodes de déploiement) 2.4.5 - 2.4.9

>[!NOTE]
>
>Le correctif peut s’appliquer à d’autres versions avec de nouvelles versions de [!DNL Quality Patches Tool]. Pour vérifier si le correctif est compatible avec votre version d’Adobe Commerce, mettez à jour le package `magento/quality-patches` vers la dernière version et vérifiez la compatibilité sur la page [[!DNL Quality Patches Tool] : Rechercher des correctifs](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=fr). Utilisez l’ID du correctif comme mot-clé de recherche pour localiser le correctif.

## Problème

La mauvaise page CMS de restriction de site web est diffusée sur le storefront du site web secondaire dans les configurations multi-sites, car la clé de cache de la page de destination n’est pas étendue par site web.

<u>Conditions préalables</u> :

Inventaire installé.

<u>Procédure à suivre </u> :

1. Créez deux sites web.
1. Créez deux pages CMS, ajoutez du texte différent à chaque page dans la section de contenu et affectez chaque page à un site web différent.
1. Activez les restrictions de site web et configurez une page de destination pour le site web correspondant.
1. Assurez-vous que la mise en cache est activée.
1. Ouvrez le storefront du premier site web et vérifiez le contenu de la page de destination affichée.
1. Ouvrez le storefront du deuxième site web et notez qu’il affiche toujours le contenu de la page de destination du premier site web.

<u>Résultats attendus</u> :

Chaque site web affiche correctement sa page CMS respective sur le storefront.

<u>Résultats réels</u> :

Les deux sites web affichent la même page CMS, à savoir la page qui a été consultée en premier.
